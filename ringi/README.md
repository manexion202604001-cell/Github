# 稟議システム(多段階承認・差し戻し)

社内向けの稟議(申請→承認)ワークフローシステム。顧客台帳と同じ「ビルド不要の静的ページ + Supabase(任意・無料)」構成です。

## できること

- **稟議書の作成・申請** — 件名 / 分類 / 金額 / 希望期日 / 内容。下書き保存、複製、印刷対応。稟議番号(`R-2026-0001` 形式)を申請時に自動採番
- **多段階承認** — 承認ルートを何段階でも設定可能。各ステップに承認者を複数指定でき、「全員の承認が必要」「誰か1名でOK」を選択可能。STEP 1 から順に進み、最終ステップの承認で決裁完了
- **差し戻し** — 承認者はコメント付きで差し戻し可能。差し戻し先は
  - **申請者** … 申請者が内容を修正して再申請(版数が上がり、承認は最初からやり直し)
  - **任意の前ステップ** … 指定ステップ以降の承認をクリアし、そのステップから承認をやり直し
- **却下 / 取り下げ** — 却下は理由コメント必須。申請者は承認中でも取り下げ可能
- **承認ルートテンプレート** — 金額帯(例: 10万円未満 → 課長のみ、50万円以上 → 社長まで)ごとにテンプレートを登録し、稟議書作成時にワンクリック適用 or 金額から自動選択
- **履歴・コメント** — 申請 / 承認 / 差し戻し / 却下などの全アクションをタイムスタンプ・実行者・コメント付きで記録。承認可否に影響しない自由コメント欄も別途あり
- **受信箱** — 「あなたの承認待ち」フィルタと未処理件数バッジで、自分が対応すべき稟議がすぐわかる
- **メンバー管理** — 氏名 / 部署 / 役職 / 権限(管理者・一般)。管理者のみメンバー・テンプレート管理と稟議書の削除が可能

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体(これ1枚で動きます) |
| `config.js` | Supabase接続情報とパスコードの設定(任意) |
| `setup.sql` | Supabase利用時に最初に1回実行するSQL |

## 使い方

### そのまま使う(共有なし・お試し)

`ringi/index.html` をブラウザで開くだけで動きます。データはそのブラウザの localStorage に保存されます。初回画面の「サンプルデータで試す」でメンバー4名・承認ルート3種・稟議書2件が入り、すぐに承認フローを体験できます。

### 全員でデータを共有する(Supabase・無料)

1. https://supabase.com でプロジェクトを作成(顧客台帳と同じプロジェクトでOK)
2. SQL Editor で `setup.sql` を実行
3. Project Settings → API の「Project URL」「anon public」キーを `config.js` に貼り付け
4. GitHub に push(GitHub Pages で自動公開)→ `https://<アカウント>.github.io/<リポジトリ>/ringi/` を全員に共有

Supabase を設定すると、承認・差し戻しなどの操作が他メンバーの画面にもリアルタイムで反映されます。画面右上が「● 同期オン」になっていれば共有状態です。

## 運用メモ

- 「操作中」ユーザーは画面右上で切り替えます(端末ごとに記憶)。小規模チーム向けの性善説運用で、本格的な認証はありません
- `config.js` の `APP_PASSCODE` を設定すると簡易パスコード画面を挟めます(社外の抑止用)
- 設定 → データ から JSON エクスポート / インポートでバックアップ・移行ができます
- anonキーは公開前提のキーです。**service_role キーは絶対に config.js に書かない**でください
